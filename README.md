\# ValutaTrade Hub



Консольное Python-приложение для работы с виртуальным валютным портфелем и актуальными курсами валют. Проект реализован в рамках итоговой работы по дисциплине «Программирование на Python».



\## Возможности



Приложение позволяет:



\- регистрировать пользователей

\- выполнять вход в систему

\- хранить пользовательские портфели

\- покупать и продавать виртуальные валюты

\- рассчитывать стоимость портфеля в выбранной базовой валюте

\- получать текущий курс между двумя валютами

\- просматривать таблицу актуальных курсов

\- выводить топ самых дорогих криптовалют

\- получать актуальные курсы из внешних API

\- хранить историю обновлений курсов

\- автоматически обновлять устаревший кэш

\- выполнять периодическое обновление курсов через планировщик

\- вести журналы пользовательских операций и работы парсер сервиса



\## Поддерживаемые валюты



Фиатные валюты:



\- USD = US Dollar

\- EUR = Euro

\- RUB = Russian Ruble



Криптовалюты:



\- BTC = Bitcoin

\- ETH = Ethereum

\## Архитектура



Проект разделён на несколько логических слоёв.



\### CLI



valutatrade\_hub/cli/interface.py



Отвечает за:



\- чтение команд пользователя

\- разбор аргументов

\- хранение текущей пользовательской сессии

\- вызов функций из usecases.py

\- форматирование результатов;

\- вывод таблиц через PrettyTable

\- обработку ошибок на уровне пользовательского интерфейса



CLI не работает напрямую с json-файлами и не выполняет основные бизнес-расчёты.



\### Core



valutatrade\_hub/core/



Содержит основную предметную модель приложения:



\- `User`

\- `Wallet`

\- `Portfolio`

\- абстрактный класс Currency

\- `FiatCurrency`

\- `CryptoCurrency`

\- пользовательские исключения

\- декоратор @log\_action

\- бизнес-сценарии приложения



\### Infra



valutatrade\_hub/infra/



Отвечает за инфраструктурные компоненты:



\- загрузку настроек

\- работу с JSON-хранилищем

\- конфигурацию логирования



`SettingsLoader` и `DatabaseManager` реализованы как Singleton.



Запись json-файлов выполняется атомарно: данные сначала записываются во временный файл, после чего основной файл заменяется через атомарную операцию.



\### Parser Service



valutatrade\_hub/parser/



Отвечает за получение валютных курсов из внешних API.



Используются:



\- CoinGecko для BTC и ETH

\- ExchangeRate-API для EUR и RUB



Parser Service поддерживает частичный отказ источников: если один API недоступен, успешно полученные курсы сохраняются, а значения от недоступного источника остаются из предыдущего кэша вместе с их прежним временем обновления.



Если недоступны все API, текущий кэш не перезаписывается пустыми данными.

```text

register --username alice --password 1234

```



При регистрации создаются пользователь и пустой портфель.



\### Вход



```text

login --username alice --password 1234

```



После успешного входа текущая сессия хранится внутри запущенного CLI-процесса.



Повторный успешный `login` заменяет текущего пользователя.



\### Просмотр портфеля



В USD:



```text

show-portfolio

```



В другой поддерживаемой валюте:



```text

show-portfolio --base EUR

```



Результат выводится через PrettyTable.



\### Покупка валюты



```text

buy --currency BTC --amount 0.01

```



Если кошелька с указанной валютой ещё нет, он создаётся автоматически.



\### Продажа валюты



```text

sell --currency BTC --amount 0.005

```



При недостаточном балансе возникает `InsufficientFundsError`.



\### Получение курса



```text

get-rate --from BTC --to USD

```



Пример:



```text

Курс BTC->USD: 81000.00

Обратный курс USD->BTC: 0.00001235

```



Обратный курс рассчитывается из исходного неокруглённого значения. Округление применяется только при выводе результата.



Если кэш курсов устарел, приложение пытается автоматически обновить его через Parser Service.



\### Просмотр всех курсов



```text

show-rates

```



Команда выводит текущий кеш в виде таблицы с:



\- кодом валюты

\- курсом к USD

\- источником

\- временем обновления



\### Топ криптовалют



```text

show-rates --top 2

```



Параметр --top N показывает N самых дорогих криптовалют по отношению к USD.



Фиатные валюты в этот рейтинг не включаются.



\### Принудительное обновление курсов



```text

update-rates

```



Команда обращается к внешним API и обновляет локальный кеш.



Во время явного обновления основные сообщения Parser Service выводятся в консоль. Более подробная диагностическая информация сохраняется в logs/parser.log.



\### Выход



```text

exit

```



или:



```text

quit

```



\## Модель операций buy и sell



В проекте используется упрощённая модель виртуального портфеля.



При выполнении:



```text

buy --currency BTC --amount 0.01

```



баланс BTC увеличивается на указанное количество, а приложение рассчитывает оценочную стоимость покупки в USD.



Средства с USD-кошелька не списываются.



При выполнении:



```text

sell --currency BTC --amount 0.005

```



баланс BTC уменьшается, а приложение рассчитывает оценочную выручку в USD.



Выручка не зачисляется на USD-кошелёк.



USD используется как базовая валюта для оценки стоимости активов.



Такой подход позволяет работать с пустым портфелем после регистрации без отдельной команды пополнения баланса.



\## Хранение данных



\### data/users.json



Содержит пользователей приложения.



Пароли в открытом виде не сохраняются. Для каждого пользователя сохраняются соль и хеш пароля.



\### data/portfolios.json



Содержит пользовательские портфели и балансы валютных кошельков.



\### data/rates.json



Хранит текущий снимок валютных курсов.



Формат:



```json

{

&#x20;   "pairs": {

&#x20;       "BTC\_USD": {

&#x20;           "rate": 81000.0,

&#x20;           "updated\_at": "2026-10-18T18:30:00Z",

&#x20;           "source": "CoinGecko"

&#x20;       }

&#x20;   },

&#x20;   "last\_refresh": "2026-10-18T18:30:00Z"

}

```



Все временные метки курсов сохраняются в UTC.



\### data/exchange\_rates.json



Содержит накопительную историю полученных валютных курсов.



Для каждой записи формируется уникальный идентификатор на основе валютной пары и времени обновления.



Повторные записи с одинаковым идентификатором не добавляются.



\## Кэширование курсов



По умолчанию срок актуальности кэша задаётся параметром:



```toml

rates\_ttl\_seconds = 300

```



Если кэш старше установленного TTL, команды, которым необходим актуальный курс, инициируют обновление через Parser Service.



\## Планировщик



В valutatrade\_hub/parser/scheduler.py реализовано периодическое обновление курсов.



Интервал задаётся в pyproject.toml.



Планировщик можно запустить отдельно:



```bash

uv run python

```



```python

from valutatrade\_hub.parser.scheduler import run\_scheduler



run\_scheduler()

```



Для остановки:



```text

Ctrl+C

```



Планировщик не запускается автоматически вместе с основным CLI.



\## Логирование



Приложение использует два основных журнала.



\### logs/actions.log



Содержит операции покупки и продажи.



Пример:



```text

INFO ... BUY user\_id=1 currency=BTC amount=0.01 rate=81000.0 result=OK

INFO ... SELL user\_id=1 currency=BTC amount=0.005 rate=81000.0 result=OK

```



При ошибках сохраняется `result=ERROR` и диагностическая информация.



\### logs/parser.log



Содержит информацию о работе Parser Service:



\- запуск обновления

\- обращения к API

\- успешные ответы

\- ошибки источников

\- запись курсов

\- работу планировщика



Каталог logs/ не хранится в Git.



\## Обработка ошибок



В проекте используются собственные исключения:



\- InsufficientFundsError - недостаточный баланс

\- CurrencyNotFoundError - неизвестная валюта

\- ApiRequestError - ошибка получения данных от внешнего API



Ошибки обрабатываются в CLI и выводятся пользователю без аварийного завершения приложения.

\## Особенности реализации



\- бизнес-логика отделена от CLI

\- модели не работают напрямую с json-хранилищем

\- пользовательская сессия существует только во время работы CLI

\- DatabaseManager и SettingsLoader реализованы как Singleton

\- валюты реализованы через абстрактный базовый класс и наследование

\- buy и sell логируются через декоратор @log\_action

\- внешние API вызываются через библиотеку requests

\- кэш поддерживает частичное обновление при отказе одного источника

\- запись json выполняется атомарно

\- курс конвертации рассчитывается через USD

\- данные о времени обновления хранятся в UTC
